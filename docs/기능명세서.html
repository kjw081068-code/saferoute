1프로젝트 개요

Safe Route Sinlim은 서울특별시 관악구·동작구 일대를 대상으로 CCTV, 가로등, 보안등, 편의점, 경찰서/지구대, 유흥시설 데이터를 결합하여 야간 보행 안전점수를 산출하고, TMAP 도보 API 경로 위에 안전한 우회를 자동 적용하여 최적 안전경로를 제공하는 웹 서비스입니다.

Gemini 2.5 Flash AI가 경로의 안전 특성을 분석하여 보행자에게 실질적인 행동 조언을 제공합니다.

격자 사전계산 (make_safety_grid.py)

100m × 100m 격자 생성 과정

  1. 위경도 → 미터 변환 (REF_LAT=37.47 기준 cos 보정)
  2. 영역 전체를 STEP_LAT=100/111320, STEP_LNG=100/(111320×cos(37.47°)) 간격으로 격자 분할
  3. 각 격자 중심에서 cKDTree query_ball_point로 반경 내 시설 집계
  4. 점수 공식 적용 후 CSV로 저장 (safety_grid.csv / safety_grid_dongjak.csv)
  5. 등급 배정: 전체 격자 순위 기준 상대평가 (하위 30%=위험, 상위 30%=안전)

런타임 데이터 로딩 (지연 초기화)

전역 캐시로드 함수내용
_grid_df_load_grid()관악+동작구 격자 DataFrame (최초 호출 시 로드, 이후 캐시)

위도: lat × 111,320 / 경도: lng × 111,320 × cos(37.47°)

4안전점수 산출

안전점수는 격자 기반 사전계산과 실시간 원형 조회를 혼합하여 계산합니다. 격자에서 CCTV·보안등 기여분을 제거하고 정밀한 실시간 값으로 교체하는 방식입니다.

4.1 격자 기본 점수 공식

기본 공식 (make_safety_grid.py)

기본점수 = 40점

CCTV 가산   = min(반경 100m 내 수량 합계, 4) × 5점   (최대 20점)
가로등 가산  = min(반경  80m 내 개수,     3) × 5점   (최대 15점)
편의점 가산  = min(반경 100m 내 개수,     2) × 5점   (최대 10점)
경찰서 가산  = min(반경 300m 내 개수,     1) × 10점  (최대 10점)
유흥시설 감점 = min(반경 100m 내 개수,   3) × 3점   (최대  9점)

격자점수 = clamp(40 + CCTV + 가로등 + 편의점 + 경찰서 - 유흥시설, 10, 100)

점수 요소별 기여도

CCTV (격자 100m)
최대 20점
가로등 (격자 80m)
최대 15점
편의점 (격자 100m)
최대 10점
경찰서/지구대/파출소
최대 10점
유흥시설 (감점)
최대 -9점

4.2 실시간 원형 조회 (런타임 교체)

경로 계산 및 API 응답 시점에 격자 CCTV·보안등 기여분을 제거하고 아래 실시간 값으로 대체합니다.

CCTV — 이중 반경 (Dual-Ring)

# Inner: 15m 이내 (전체 가중치)
inner_idxs = tree.query_ball_point(pt, r=15.0)
# Outer: 15m 초과 ~ 30m 이내 (절반 가중치)
outer_idxs = tree.query_ball_point(pt, r=30.0) - inner_idxs

score = min(inner_qty, 4) × 5.0   # 최대 20점
      + min(outer_qty, 4) × 2.5   # 최대 10점
# 합계 최대 30점

동일 카메라는 inner 또는 outer 중 하나에만 포함됩니다 (set 차집합). 관악구 + 동작구 CCTV 통합 조회.

보안등 — 단일 반경 5m

# 동작구 보안등만 적용
idxs = safelight_tree.query_ball_point(pt, r=5.0)

score = min(len(idxs), 3) × 3.0
# 최대 9점

5m 이내에 보안등이 1개이상 있을 때만 가산. 관악구 가로등은 격자 계산에 반영된 상태이므로 교체하지 않음.

최종 실시간 점수 계산 (_score_for_coord)

grid_score   = 격자 기본점수 (사전계산)
old_cctv     = min(격자 cctv_count, 4) × 5    # 제거할 기존 CCTV 기여
old_safelight = min(격자 safelight_count, 3) × 3  # 제거할 기존 보안등 기여

new_cctv      = _cctv_score_for_coord(lat, lng)        # 실시간 이중반경
new_safelight = _safelight_score_for_coord(lat, lng)   # 실시간 5m

adjusted = clamp(
    grid_score - old_cctv - old_safelight + new_cctv + new_safelight,
    10.0, 100.0
)

4.3 등급 판정

런타임 등급은 격자 전체 score의 절대 백분위수 임계값으로 결정합니다. 격자 수정 없이 재호출만으로 등급 경계를 자동 계산합니다.

등급조건기준 (예시)표시 색상
위험 score < 격자 30 백분위수 ~약 40점 빨간색
보통 30 백분위수 ≤ score < 70 백분위수 약 40~55점 노란색
안전 score ≥ 격자 70 백분위수 55점 이상~ 초록색
ℹ️ 격자 grade 컬럼은 사전계산 시 상대평가로 배정됩니다. 런타임 등급(score_to_grade_realtime)은 절대 임계값으로 판정하므로, 실시간 조정 후에도 일관성 있는 등급 기준이 적용됩니다.

5.2 안전경로 알고리즘 (_build_safe_route)

일반경로를 기반으로 위험 구간을 감지하고, 수직 우회 포인트(W)를 삽입하여 TMAP API를 재호출합니다.

우회 생성 4단계

  1. 위험 구간 식별: 샘플링된 좌표에서 연속적으로 등급이 "안전"이 아닌 구간을 그룹화
  2. 우회 포인트(W) 선택: 위험 구간 중간점에서 진행 방향 수직으로 좌/우 각 100m 지점 계산 → 더 안전한 점(W)을 선택
  3. 우회 가치 검증: W_score > stretch_avg일 때만 TMAP A→W→B 재호출
  4. 우회 적용 여부 확정: 재호출 결과 alt_avg > stretch_avg일 때만 우회 구간으로 교체
A 지점위험 구간
진입 직전 안전점

5.3 Fallback 조건

⚠️ 아래 조건 중 하나라도 충족되면 안전경로를 포기하고 일반경로를 "safe" 타입으로 반환합니다.
  • 안전경로 avg_score < 일반경로 avg_score (우회가 오히려 더 위험)
  • 안전경로 소요시간 > 일반경로 소요시간 × 1.3 (30% 이상 지연)

6AI 경로 분석 (Gemini)

항목내용
엔드포인트POST /api/route-description
AI 모델Gemini 2.5 Flash (gemini-2.5-flash)
호출 시점경로 탐색 완료 후 사용자가 결과 확인 시

요청 / 응답 구조

요청 (RouteDescriptionRequest)
  • segments: 경로 구간 목록 (grade, 시설 수치)
  • avg_score: 전체 평균 안전점수
  • grade: 전체 등급 ("안전"/"보통"/"위험")
응답 (RouteDescriptionResponse)
  • safe_points: 안전한 이유 2가지 이내
  • warning_points: 위험 요인 2가지 이내
  • ai_summary: 보행자 행동 조언 2문장 이내

프롬프트 설계 방향

  • 안전/보통/위험 구간 비율과 CCTV·가로등·편의점·유흥시설 수치를 근거로 설명 생성
  • 수치 및 점수 언급 금지 — 실제 보행자 행동 조언만 작성
  • 유흥시설이 많은 경우 야간 주취자 위험 언급
  • 출력 포맷: 순수 JSON (마크다운·코드블록 금지)

12제약 및 한계

데이터 커버리지
  • 편의점·유흥시설·경찰서는 관악구만 적용 (동작구 미포함)
  • 보안등 실시간 조회는 동작구만 적용 (관악구 격자 포함)
  • 가로등 격자는 관악구+동작구 통합이나, 실시간 교체는 동작구 보안등만
  • 데이터 최신성: 공공데이터 기준일 이후 변경 미반영
경로 알고리즘 한계
  • 우회 포인트(W)는 수직 방향 100m 고정 — 실제 도로망 미고려
  • 우회 호출 횟수 제한 없음 — 복잡한 경로에서 API 과다 호출 가능
  • TMAP 재호출 결과가 W를 실제로 지나지 않을 수 있음
  • 일반경로가 안전경로보다 점수 높으면 fallback (두 경로 동일 표시)
성능
  • 격자 DataFrame·KDTree는 최초 요청 시 지연 로드 (Cold Start 지연)
  • 경로 길이에 따라 100m 간격 샘플링 + KDTree 조회 횟수 선형 증가
  • Railway 무료 플랜은 비활성 시 슬립 — 첫 요청 지연 가능
UI 단일 컴포넌트
  • 전체 UI 로직이 App.tsx 단일 파일에 집중
  • 컴포넌트 분리 없어 기능 추가 시 파일 규모 증가
  • 상태 관리 라이브러리 미사용 (useState만 사용)

알려진 동작 특이사항

⚠️ 일반경로 미표시 현상: 안전경로 fallback이 발생하면 두 경로가 동일한 좌표를 가집니다. 이 경우 안전경로(파란색) 폴리라인이 일반경로(회색) 위에 겹쳐 일반경로가 보이지 않는 것처럼 보일 수 있습니다.
