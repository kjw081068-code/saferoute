1프로젝트 개요

Safe Route Sinlim은 서울특별시 동작구를 대상으로 CCTV, 가로등, 보안등, 편의점/24시 점포, 경찰/지구대, 소방서, 유흥주점 데이터를 결합하여 보행 안전점수를 산출하고, TMAP 도보 API 경로 위에 안전한 우회를 자동 적용하여 안전경로를 제공하는 웹 서비스(로컬 실행 기준)입니다.

Gemini 2.5 Flash AI가 경로의 안전 특성을 분석하여 보행자에게 실질적인 행동 조언을 제공합니다.

데이터 처리 방식 (로컬 기준)

KDTree 기반 근접 조회

  1. 각 CSV(시설 좌표)를 로드해 KDTree를 구성합니다.
  2. 점수 계산 시 좌표 주변 반경(또는 최근접 거리)을 조회하여 요소별 점수를 계산합니다.
  3. 일부 요소는 중복 시 한계편익체감(편의+24시, CCTV 원거리) 또는 거리 비례 감쇠(경찰/소방)를 적용합니다.
  4. 등급은 백분위가 아닌 절대 임계값(S<0, S<20)으로 판정합니다.

4안전점수 산출

안전점수는 실시간 반경(또는 최근접 거리) 기반 가중합으로 계산합니다. 각 요소는 KDTree로 근접 데이터를 조회하고, 일부 요소는 중복 시 한계편익 체감 또는 거리 비례 감쇠를 적용합니다.

4.1 점수 공식 (현행)

총합 공식

S = B(주간 활동성)
  + CCTV
  + 가로등
  + 보안등
  + 편의점+24시(한 레이어)
  + 경찰(거리감쇠)
  + 소방(거리감쇠)
  - 유흥(감점)

시간대는 한국시 기준으로 구분합니다. 주간(08~22) / 야간(22~익일 08).

한계편익체감(공통 함수)

n번째 개체 기여도 = base × (1-rate)^(n-1)
총합 = Σ_{k=1..n} base × (1-rate)^(k-1)
이론 수렴 최대 = base / rate

5.2 안전경로 알고리즘 (_build_safe_route)

일반경로를 기반으로 위험 구간을 감지하고, 수직 우회 포인트(W)를 삽입하여 TMAP API를 재호출합니다.

우회 생성 4단계

  1. 위험 구간 식별: 샘플링된 좌표에서 연속적으로 등급이 "안전"이 아닌 구간을 그룹화
  2. 우회 포인트(W) 선택: 위험 구간 중간점에서 진행 방향 수직으로 좌/우 각 100m 지점 계산 → 더 안전한 점(W)을 선택
  3. 우회 가치 검증: W_score > stretch_avg일 때만 TMAP A→W→B 재호출
  4. 우회 적용 여부 확정: 재호출 결과 alt_avg > stretch_avg일 때만 우회 구간으로 교체

5.3 Fallback 조건

⚠️ 아래 조건 중 하나라도 충족되면 안전경로를 포기하고 일반경로를 "safe" 타입으로 반환합니다.
  • 안전경로 avg_score < 일반경로 avg_score (우회가 오히려 더 위험)
  • 안전경로 소요시간 > 일반경로 소요시간 × 1.3 (30% 이상 지연)

6AI 경로 분석 (Gemini)

항목내용
엔드포인트POST /api/route-description
AI 모델Gemini 2.5 Flash (gemini-2.5-flash)
호출 시점경로 탐색 완료 후 사용자가 결과 확인 시

요청 / 응답 구조

요청 (RouteDescriptionRequest)
  • segments: 경로 구간 목록 (grade, 시설 수치)
  • avg_score: 전체 평균 안전점수
  • grade: 전체 등급 ("안전"/"보통"/"위험")
응답 (RouteDescriptionResponse)
  • safe_points: 안전한 이유 2가지 이내
  • warning_points: 위험 요인 2가지 이내
  • ai_summary: 보행자 행동 조언 2문장 이내

프롬프트 설계 방향

  • 안전/보통/위험 구간 비율과 CCTV·가로등·편의점·유흥시설 수치를 근거로 설명 생성
  • 수치 및 점수 언급 금지 — 실제 보행자 행동 조언만 작성
  • 유흥시설이 많은 경우 야간 주취자 위험 언급
  • 출력 포맷: 순수 JSON (마크다운·코드블록 금지)

12제약 및 한계

데이터 커버리지
  • 현재 로컬 기준 데이터 커버리지는 동작구 중심입니다.
  • 관악구 관련 CSV/코드는 일부 남아있지만, 현행 점수/경로 로직에서는 기본적으로 비활성화되어 있습니다.
  • 데이터 최신성: 공공데이터 기준일 이후 변경 미반영
경로 알고리즘 한계
  • 우회 포인트(W)는 수직 방향 100m 고정 — 실제 도로망 미고려
  • 우회 호출 횟수 제한 없음 — 복잡한 경로에서 API 과다 호출 가능
  • TMAP 재호출 결과가 W를 실제로 지나지 않을 수 있음
  • 일반경로가 안전경로보다 점수 높으면 fallback (두 경로 동일 표시)
성능
  • KDTree는 최초 요청 시 지연 로드(초기 로딩 지연 가능)
  • 경로 길이에 따라 100m 간격 샘플링 + KDTree 조회 횟수 선형 증가
  • 로컬 환경 성능은 PC/네트워크(특히 TMAP 호출)에 영향을 받음
UI 단일 컴포넌트
  • 전체 UI 로직이 App.tsx 단일 파일에 집중
  • 컴포넌트 분리 없어 기능 추가 시 파일 규모 증가
  • 상태 관리 라이브러리 미사용 (useState만 사용)

알려진 동작 특이사항

⚠️ 일반경로 미표시 현상: 안전경로 fallback이 발생하면 두 경로가 동일한 좌표를 가집니다. 이 경우 안전경로(파란색) 폴리라인이 일반경로(회색) 위에 겹쳐 일반경로가 보이지 않는 것처럼 보일 수 있습니다.
